# SSRF 安全 HTTP 客户端设计

## 目标

为用户可控的图片和文件 URL 提供 DNS 重绑定防护，同时继续遵循 `HTTP_PROXY`、`HTTPS_PROXY` 和 `NO_PROXY` 环境变量。

## 安全边界

- 新客户端仅用于本机直接抓取用户可控 URL；普通上游 API 客户端保持不变。
- SSRF 防护开启时，域名必须在连接前完成一次 DNS 解析，解析结果必须符合现有私有地址和 IP 名单规则。
- `AllowPrivateIp` 为 `false` 时始终拒绝解析到私有、回环、链路本地、未指定和保留地址的域名；`ApplyIPFilterForDomain` 只控制自定义 IP 名单是否应用于域名。
- 同一次请求只使用本次已校验的 IP 建立连接，连接阶段不再解析目标域名。
- 每次重定向都按新目标重新执行完整校验、解析和固定 IP 流程。

## 请求流程

1. 使用现有 SSRF 配置校验 URL 协议、端口和域名规则。
2. IP 字面量直接校验；域名只解析一次，并拒绝任一不允许的解析结果。
3. 在改写请求前调用 `http.ProxyFromEnvironment`，确保代理和 `NO_PROXY` 判断使用原始域名。
4. 将实际连接目标固定为已校验 IP，同时保留原始 `Host`。
5. HTTPS 请求继续使用原始域名作为 TLS SNI 和证书校验名称；HTTP/HTTPS 代理收到的连接目标为固定 IP。
6. 响应结束后关闭本次连接，不进入连接池，避免跨请求复用不同 DNS 校验结果。

## 代码范围

- 在 `service` 包新增 SSRF 安全 HTTP 客户端及其最小测试入口。
- `DoDownloadRequest` 的非 Worker 路径改用新客户端；Claude、AWS、Ollama 和 Gemini 的图片下载会通过现有共享调用链自动获得防护。
- Worker 路径保持不变，因为真正的目标连接发生在 Worker，Worker 侧需要独立实现同类防护。
- 不新增第三方依赖，不改渠道代理客户端，不改无关业务逻辑。

## 错误处理

- DNS 解析失败、任一解析结果不允许、代理配置错误或 TLS 校验失败时直接终止请求并返回错误。
- 错误信息包含被拒绝的主机或 IP，但不输出代理认证信息及完整敏感 URL。

## 验证

- 测试 DNS 首次返回公网 IP、后续返回内网 IP 时，客户端只解析一次并连接首次校验的公网 IP。
- 测试解析结果包含私有地址时在连接前拒绝。
- 测试 HTTP/HTTPS 代理路径固定目标 IP，并保留原始 `Host` 与 TLS ServerName。
- 测试 `NO_PROXY` 判断基于改写前的原始域名。
- 测试重定向目标重新解析并校验。
- 运行相关 Go 单元测试、`go test ./common ./service` 和项目可行的全量 Go 测试。
